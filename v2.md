# v2 — units and accumulated fields

Follow-on to Release 1 (see `CLAUDE.md`). R1 shipped a correct reader and a working
two-panel viewer that displays **raw file values only**. v2 makes the numbers on screen the
numbers a forecaster actually reads.

| in scope | delivers |
|---|---|
| **A — unit conversion**, defaulting to **°C** for temperature | nobody subtracts 273.15 in their head forty times a session |
| **B — every units string correct for all 15 fields**, incl. **cloud cover as %** | a wrong or missing conversion is worse than no conversion; this is measured, not assumed |
| **C — de-accumulation** of accumulated/averaged fields to **hourly** and **3-hourly** | cumulative precip cannot answer "will it rain at 14Z" |

**Deferred** (design retained in §5): probability of exceedance, wind speed/direction.
**v3** (§6): side-by-side fields, built-in downloader.

`CLAUDE.md` §0 stays the contract; its byte math is not re-derived here. Everything below
marked *measured* was measured on 2026-08-24 against the files in `data/`.

---

## 0. Architecture — one transform layer

### 0.1 The trap

Both A and C are *transformations applied between the file and the screen*. There are
already four consumers of raw values — `refresh_map`, `PlotView.set_series`,
`member_stats` → `ReadoutPanel`, and the `cursorMoved` status-bar readout. Converting at
each call site means four chances to drift, and the failure mode is the map reading °C
while the readout reads K, or the graph showing a rate while the hover readout shows a
cumulative total. Silently inconsistent is worse than absent.

### 0.2 The decision: `FieldView`, a transparent decorator

```
   memmap ─► EnsembleFile ──────────────► raw physical values (R1 code, unmodified)
                  │                        tests/test_dataset.py stays green untouched
                  ▼
             FieldView  ◄── Transform (rate ∘ units) ── NEW
                  │
       ┌──────────┼──────────┬───────────────┐
       ▼          ▼          ▼               ▼
    MapView   PlotView   ReadoutPanel   status bar
```

`FieldView` mirrors the attribute surface `EnsembleFile` already exposes, so `main.py`
changes one line:

```python
self.ds = FieldView(EnsembleFile(path))     # was: self.ds = EnsembleFile(path)
```

and `MapView`, `PlotView` and `ReadoutPanel` need **no change at all**. That is the point:
the diff stays small and the four consumers *cannot* disagree, because there is one place
values are produced.

| surface | treatment |
|---|---|
| `lat lon dlat dlon ny nx n_times n_members member_labels times forecast_hours run_init path` | delegated verbatim (`__getattr__` fallback) |
| `nearest_index() extent()` | delegated verbatim |
| `frame() ens_frame() agg_frame() series()` | **overridden** — transform applied |
| `field long_name units value_range summary() label_for()` | **overridden** — the label must describe the *transformed* quantity |
| `set_units() set_rate() unit_choices rate_choices` | new |

`EnsembleFile` is not modified. Keeping it pure as the raw-truth layer is exactly what lets
the transforms be tested by round-tripping against it.

### 0.3 The ordering rule — the load-bearing correctness constraint

Transforms do **not** commute. Fixed order:

```
raw ──► [1] time-differencing ──► [2] unit conversion ──► display
```

and step [2] must know what kind of quantity step [1] produced:

| output of step [1] | unit conversion to apply |
|---|---|
| **absolute** (instantaneous field; window-*mean* of an averaged field) | full affine `a·x + b` |
| **difference** (window-*sum* of an accumulated field) | **scale only, `a·Δ`** |

A 5 K rise is a 5 °C rise, not −268.15 °C. Encoding this in the transform rather than
trusting each call site is what makes it safe — **G15**.

### 0.4 Performance budget

R1's virtue is that every read is a plain numpy slice on a memmap. Do not lose it.

| operation | reads | cost |
|---|---|---|
| unit conversion | — | one affine pass over 42 k floats — negligible |
| 1 h / 3 h rate, map frame | 2 × `ens_frame` | 2 × 3.4 MB, < 2 ms |
| 1 h / 3 h rate, point series | 1 × `series` + diff | (121, 20) — negligible |

Comfortably inside a 60 fps scrub. **Do not add frame caching.** The only real cost is the
dataset-range scan, which a rate view cannot share with the raw view — **G19**, phase V2.4.

## 1. Item B — getting all 15 units strings right

This is the part that cannot be designed, only measured. It is promoted to its own phase
because a plausible-but-wrong conversion (a 100× cloud cover, a −273 °C rate) is the worst
outcome v2 can produce.

**Two findings that changed the code or the contract:**

1. **Cloud cover is `%` (0–100), not the 0–1 fraction `CLAUDE.md` §0.2 documented.** All four
   fields report `units='%'` with values spanning 0..100. §1.5's insistence on deciding from
   the *data range* is exactly what caught this: had the registry trusted "0–1" and offered
   a ×100, every cloud map would have read 100× high. The gate stays in place regardless,
   because the encoding is a property of the data, not of the header.
2. **The radiation spelling is `W/m**2`.** The **G21** normaliser maps it to `W m-2` with no
   registry change — which is the whole reason §1.6 exists. Had units been compared
   literally, both radiation fields would have silently lost their conversion *and* their
   de-accumulation.

The two `long_name`s settle the accumulation kinds beyond argument: the radiation fields say
**"mean since model start"** (⇒ `mean`) and `VMAX_10M` says **"since end of previous full
01H interval"** (⇒ already per-interval, never difference it).

The product PDF in the repo root (`IMS_ICON_ENS.pdf`) does **not** help: it is a subset-font
Hebrew document whose text layer does not extract, and its field table is what `CLAUDE.md`
§0.2 already records. It was not needed.

### 1.2 Sniffing a header without downloading 262 MB — measured, works

A `.nc.bz2` is a single bz2 stream, and bz2 decompresses incrementally. The NetCDF-3 header
sits in the first ~6 KB of the *uncompressed* stream, and the first time record follows it.
So a **prefix** of the compressed file is enough. Measured on
`ICON_ENS_2026082300_CAPE_ML.nc.bz2` (262 MB total):

| prefix fetched | decompressed | full time steps recovered |
|---|---|---|
| 64 KiB | 0 B | — (bz2 buffers a whole 900 KiB block before emitting) |
| 256 KiB | 0 B | — |
| 1 MiB | 1,637,625 B | 0 (header only) |
| **4 MiB** | **8,177,912 B** | **2** |
| 8 MiB | 17,475,602 B | 5 |
| 16 MiB | 27,221,957 B | 8 |

Verified end-to-end: parsing the 4 MiB prefix gives `units = 'J kg-1'`,
`recsize = 3,361,688` (**G2** holds), `begin = 6372`, and the t=0 frame read straight out of
the prefix is **`np.array_equal` to the same frame in the full 407 MB file**.

⇒ **4 MiB per field settles the units string and the t=0 value range. 16 MiB settles the
accumulation kind** (8 steps is plenty of monotonicity signal). Fifteen fields cost 60 MB /
180 MB instead of 3.9 GB.

Caveat: a highly compressible field can be shorter than the prefix — `H_SNOW.nc.bz2` is
**125,788 B total** (all-zero summer snow). The sniffer must treat "stream ended" as
success, not as an error.

### 1.3 Registry policy — field name is the key, units string is a guard

```
key on field name (unambiguous)  ─►  expected units string (assertion)
                                 ─►  ordered conversions, first = default
```

If a file's units string does not match what the registry expects for that field, **warn
and offer no conversion**, falling back to R1 behaviour. A mismatch means IMS changed
something, and the safe response to "my assumption may be stale" is to stop converting, not
to guess. An unknown field likewise gets no conversion and still opens normally.

### 1.4 The registry (defaults chosen, verification status explicit)

| field | expected units | measured? | display default | conversions offered |
|---|---|---|---|---|
| `CAPE_ML` | `J kg-1` | ✅ | `J kg-1` | — none — |
| `T_2M` | `K` | ✅ | **`°C`** | °C `(1, −273.15)`, K, °F `(1.8, −459.67)` |
| `T_S` | `K` | ✅ | **`°C`** | as above |
| `RELHUM_2M` | `%` | ✅ | `%` | — none — |
| `TOT_PREC` | `kg m-2` | ✅ | **`mm`** `(1, 0)` | mm, kg m-2 |
| `U_10M`, `V_10M` | `m s-1` | ✅ | `m s-1` | m s-1, kt `(1.9438445, 0)`, km h-1 `(3.6, 0)` |
| `VMAX_10M` | `m s-1` | ✅ | `m s-1` | as above |
| `CLCT`,`CLCL`,`CLCM`,`CLCH` | `1` / `%` | ✅ **measured `%`, values 0–100 — §1.5 verdict was PERCENT** | `%` | — none, the data is already % — |
| `ASWDIFD_S`, `ASWDIR_S` | `W/m**2` → `W m-2` | ✅ | `W m-2` | — none — |
| `H_SNOW` | `m` | ✅ | **`cm`** `(100, 0)` | cm, m, mm |

**Implemented in `imsicon/transform.py:UNITS`, and every row is now ✅** — measured against
run `2026082400` on 2026-08-24 and pinned by `test_units.py::MEASURED`, which fails loudly
if IMS ever changes a spelling. Opening all 15 real fields produces **zero** mismatch
warnings. Cloud cover remains gated on the §1.5 range test even though it measured as `%`,
because the encoding is a property of the data, not of the header.

Notes that are not arbitrary:
* **`kg m-2` → `mm` is exact and free.** Water density 1000 kg m⁻³, so 1 kg m⁻² spread over
  1 m² is 10⁻³ m³ ⇒ **1 mm** exactly. The number does not change, only the label — pure
  readability, zero risk. Default it on.
* **`1 m s-1 = 3600/1852 = 1.9438445 kt`**, exact by the definition of the nautical mile
  (measured).
* Defaults change the displayed *number* only where asked (°C) or where it is unambiguously
  more readable (cm for snow, % for cloud). `VMAX_10M` stays in file units — guessing that
  a forecaster wants knots is a preference, not a fact.

### 1.5 Cloud cover — the decisive test

`CLAUDE.md` §0.2 says `CLCT/CLCL/CLCM/CLCH` are 0–1. ICON commonly publishes cloud cover in
**%** (0–100). Offering a ×100 conversion against a field already in % is a silent 100×
error, and the units string alone does not settle it (a file may say `1` and store 0–100).
**The data range does.** Using the §1.2 sniff over 8 time steps:

| observation | conclusion | action |
|---|---|---|
| any value `> 1.0` | stored as **%** | no conversion; label `%` |
| max ≈ 1.0, values spread over (0, 1) | stored as **fraction** | offer `×100 → %`, default on |
| all values ≈ 0 across all 8 steps | **undecidable** (clear sky) | **refuse to convert**, warn, sniff a different run |

Record the outcome in §1.1's table and pin it in a test. This same range check is a
permanent runtime guard, not just a one-off: if a future file's cloud cover exceeds 1.0
while the registry says "fraction", disable the conversion and warn.

### 1.6 Units-string spelling — normalise before comparing (G21)

CF units have many spellings and the merge chain (`cdo`) is not guaranteed stable across
IMS upgrades. Normalise both sides before the §1.3 guard compares them: strip, collapse
whitespace, lowercase, delete `**` and `^`, and map `/x` → ` x-1`. Then alias to a canonical
token:

```
K      ← k, kelvin, degk, deg_k
J kg-1 ← j kg-1, j/kg, j kg**-1, j kg^-1
m s-1  ← m s-1, m/s, ms-1, m s**-1
kg m-2 ← kg m-2, kg/m2, kg m**-2
W m-2  ← w m-2, w/m2
%      ← %, percent
1      ← 1, -, "" (dimensionless; `fr_land` is measured as `-`)
```

The normaliser must be **total** — an unrecognised string returns itself and lands in the
"no conversion" branch, never an exception. A units string must not be able to crash a file
open.

## 2. Gotchas

Numbering continues from `CLAUDE.md` (which ends at G13). G16–G18 belong to the deferred
work and are kept with their numbers in §5 so cross-references stay stable.

* **G14 — `TOT_PREC` is accumulated; `ASWDIFD_S`/`ASWDIR_S` are AVERAGED. The formula
  differs, and `np.diff` is wrong for radiation.** With hours-since-init `h[t]`:

  | kind | stored `A[t]` means | window `(t−k, t]` value |
  |---|---|---|
  | `sum` (`TOT_PREC`) | total over `[0, t]` | `A[t] − A[t−k]`, units per k hours |
  | `mean` (`ASWDIFD_S`, `ASWDIR_S`) | mean over `[0, t]` | `(A[t]·h[t] − A[t−k]·h[t−k]) / (h[t] − h[t−k])`, units unchanged |

  Applying the `sum` formula to radiation yields numbers that look like plausible W m⁻² and
  are not. Detection guard: an accumulated field is monotonically non-decreasing in time; an
  averaged one is not. The §1.2 sniff over 8 steps settles it per field, and the same check
  runs at load time over a sample of points, warning when registry and data disagree.
* **G15 — an affine conversion must not apply its offset to a difference.** `K → °C` is
  `a=1, b=−273.15`; on a 1-hourly *difference* only `a` contributes. Note the asymmetry with
  G14: an averaged field's window value is a *mean*, which is absolute and takes the **full**
  affine — only the `sum` branch produces a difference.
* **G19 — the `.imsstats.json` sidecar holds the RAW range and a rate view cannot reuse
  it.** Schema must grow from one `{min, max}` to a dict keyed by a transform signature. A
  pure unit change is the exception: it is affine, so transform the cached range
  (`[a·lo + b, a·hi + b]`, ends swapped if `a < 0`) instead of rescanning.
* **G20 — `float(np.nanmax(frame)) or 1.0` does not do what it looks like.** Existing latent
  bug at [main.py:340](imsicon/ui/main.py:340). Measured: `bool(float('nan'))` is `True`, so
  `nan or 1.0` evaluates to `nan`, and the `if hi <= lo` guard in `set_frame` does not fire
  because `nan <= 0.0` is `False` — an all-NaN frame reaches `cbar.setLevels(high=nan)`.
  v2 touches this line; fix it with an explicit `np.isfinite` check.
* **G21 — units strings have many spellings; compare normalised, and never raise.** §1.6.
* **G22 — cloud-cover encoding is undecidable from the units string alone.** §1.5. Resolve
  by data range, and refuse to convert when the observation is not decisive.
* **G23 — difference in float64, not float32.** Differencing two large near-equal
  accumulations is catastrophic cancellation. float32 eps is 1.19e-7, so at a 300 mm season
  total the ulp is ≈ 3.6e-5 mm, and for radiation `A[t]·h[t]` reaches ≈ 3.6e4 with ulp
  ≈ 4.3e-3 W m⁻². Both are small against a real hourly signal, but upcasting to float64
  before the subtraction removes the entire class of concern and costs nothing at
  (121, 20) / (20, 261, 161) sizes. Do it unconditionally.
* **G24 — clamp float noise, surface real negatives.** A `sum`-kind hourly rate must be
  ≥ 0. Rounding can yield tiny negatives; clamp `|x| < eps` to 0. Anything **larger** is
  evidence the field is not actually accumulated — surface it as a warning rather than
  clamping it away, or G14 gets hidden by the fix for G23.

## 3. Implementation phases

Dependency-ordered. Total ≈ 13.5 h.

### V2.0 — synthetic NetCDF-3 writer for tests *(2 h)* — enables everything

`data/` has 2 of 15 fields, and the 407 MB reference file must never become a CI dependency
(`CLAUDE.md` Phase 10). Temperature, precip, radiation and cloud cannot otherwise be tested.

1. `tests/synth.py` — `write_nc3(path, field, units, data, *, history=None, time_units=…)`
   emitting a genuine NetCDF-3 **64-bit-offset** file: header, 4-byte-padded names, the
   `time`/`sfc`/`lat`/`lon` coordinate vars, and `<FIELD>_eps(time, sfc, lat, lon)` as a
   record variable, big-endian.
2. Tiny fixtures — 3 members × 6 steps × 4 lat × 5 lon.
3. Include a `history` string in real IMS form so `member_labels` (**G1**) is exercised.
4. Fixture factories for each shape v2 needs: a `K` temperature field, a monotone `kg m-2`
   accumulation, a `W m-2` running mean with a known underlying hourly signal, and a `1`
   cloud field in both encodings (0–1 and 0–100).

**Done when:** `nc3.parse` + `nc3.view` read a synthetic file back element-for-element,
`recsize` matches the two-record-variable rule (**G2**), and `tests/test_nc3.py`'s netCDF4
equivalence test still passes on the real CAPE file. A writer built from the spec agreeing
with a reader built from the spec is independent evidence, not a tautology.

### V2.1 — `tools/sniff_headers.py`, the measurement step *(2 h)* — **delivers B**

1. Dev-only script, **not** part of the app. `requests` + `requests-ntlm` (**G7**: plain
   Basic returns 401), credentials from `IMS_USER`/`IMS_PASS` or `keyring` — never
   hardcoded, never logged, never in a URL.
2. For each field: HTTP `Range: bytes=0-4194303` against the `.nc.bz2`, feed the prefix to
   `bz2.BZ2Decompressor`, treat a truncated stream as success (§1.2 caveat), write the
   prefix to a temp `.nc`, and `nc3.parse` it.
3. Report per field: units string, `long_name`, `recsize`, `begin`, and the min/max of the
   recovered time steps.
4. `--deep` refetches at 16 MiB for the accumulation candidates and reports **monotonicity**
   per **G14**, plus the §1.5 cloud-cover verdict.
5. Emit a ready-to-paste registry table and write the findings back into §1.1 / §1.4.

**Not a blocker.** If the server is unreachable, the registry's unmeasured rows simply stay
unverified and those fields open with no conversion (§1.3). v2 ships either way — it is just
less complete, and the table says so honestly.

Bonus: the auth + listing primitives written here are the seed of the v3 downloader (§6.2).

**Done when:** running it prints a units row for every field it can reach, the CAPE row
matches the §1.1 measured values exactly, and the cloud-cover verdict is one of the three
§1.5 outcomes — never a guess.

### V2.2 — `transform.py` + `FieldView` + the unit registry *(3 h)* — **delivers A, B**

1. `imsicon/transform.py`:
   ```python
   class Affine(NamedTuple):          # display = a * raw + b
       label: str; a: float; b: float
       def apply(self, x):       return x if (self.a, self.b) == (1.0, 0.0) else x * self.a + self.b
       def apply_delta(self, d): return d if self.a == 1.0 else d * self.a      # G15: no offset
       def invert(self, y):      return (y - self.b) / self.a
   ```
2. `normalise_units()` per §1.6 / **G21** — total, never raises.
3. `UNIT_CHOICES` per §1.4, keyed on field name with the units string as a guard (§1.3);
   mismatch ⇒ warn + no conversion. Cloud cover additionally gated on the §1.5 range test.
4. `imsicon/fieldview.py` — `FieldView` per the §0.2 surface table, `__getattr__` delegation
   for pass-throughs.
5. `units` returns the active `Affine.label`; `value_range` transforms the cached raw range
   affinely (**G19**), swapping ends if `a < 0`.
6. `main.py`: wrap the dataset; add a **second toolbar row** (`addToolBarBreak()`) for the
   units combo so the display row does not become a cockpit. Persist per field in
   `QSettings` and apply at load, so Kelvin is never shown unless asked for.
7. Re-check **G12**: `enableAutoSIPrefix(False)` already exists on the plot's left axis —
   confirm `°C`, `mm`, `kt`, `%` are not re-prefixed, and that the degree sign survives the
   Qt axis-label path **on Windows** (the target platform), not just macOS.

**Done when:** opening a `T_2M` file shows °C on the map title, colorbar, y-axis, hover
status bar and all six readout rows **simultaneously**; switching to K moves all five
together; an unknown field still opens with no conversion offered; and
`tests/test_dataset.py` is untouched and green.

### V2.3 — de-accumulation *(3 h)* — **delivers C**

1. `ACCUMULATION = {'TOT_PREC': 'sum', 'ASWDIFD_S': 'mean', 'ASWDIR_S': 'mean'}`, confirmed
   by V2.1 `--deep`. Everything else is instantaneous and the rate control stays
   **disabled** — note especially `VMAX_10M`, already a per-interval quantity ("max over
   previous 1 h", `CLAUDE.md` §0.2), which must never be differenced.
2. Window `k` in **steps**: `round(hours / median(diff(forecast_hours)))`. Do not hardcode
   1 step = 1 hour.
3. The two **G14** formulas as one function with a `kind` switch; applied along the time
   axis for `frame`/`ens_frame`/`agg_frame`, vectorised for `series`. Upcast to float64
   first (**G23**); clamp `sum`-kind noise, warn on real negatives (**G24**).
4. Window edge: `t < k` ⇒ **NaN**, not a partial window. Losing 3 of 121 steps is nothing; a
   silently-partial "3-hourly" total is a misread waiting to happen. `PlotView` already has
   the `connect='finite'` precedent — apply it to the member curves and the envelope so the
   gap renders as a gap.
5. Units label follows the kind, and it is not cosmetic:
   * `sum`, k=1 → `mm h-1`; `sum`, k=3 → `mm/3h`
   * `mean`, any k → **unchanged** (`W m-2`) — a window mean is still a mean
6. `label_for()` gains the window, so the readout says what interval the number covers:
   `2026-08-27 14:00Z (+110 h · 1 h to 14:00Z)`. A rate is **backward-looking**; a reader
   who takes it as instantaneous is off by one interval.
7. Wire `apply_delta` vs `apply` per **G15** — `sum` → delta, `mean` → full affine.

**Done when:** on a real `TOT_PREC` file, `cumsum` of the hourly rate reproduces the stored
accumulation to float32 tolerance; the 3-hourly rate at `t` equals `A[t] − A[t−3]`; the
first `k` steps render as gaps; and `ASWDIR_S` hourly means fall in the physically plausible
0–1100 W m⁻² band at local noon — the sanity check that catches a `np.diff` applied to an
averaged field.

Fast tests run on V2.0 synthetic fixtures and need no `data/`. Tests needing a real field

| `tests/test_sniff.py` | the §1.2 prefix path against the **local** `.nc.bz2` (no network): 4 MiB prefix parses, units matches, t=0 frame is `np.array_equal` to the full file, and a stream shorter than the prefix (`H_SNOW.nc.bz2`, 125,788 B) is handled as success |

Property-based invariants — round-trip, monotonicity, totality of the normaliser — are
deliberately preferred over golden numbers. They keep holding when IMS changes a value, and
they are what actually catches the G14/G15/G21 class of bug.

## 5. Deferred — probability and wind (next release after v2)

Design retained so it is not re-derived; the `FieldView` layer already accommodates both.

### 5.1 Probability of exceedance

`FieldView.probability(t, threshold_display)` → `(ens_frame_raw(t) >= units.invert(thr)).mean(axis=0)`.
Inverting the threshold once beats converting 42 k values. Use `>=` ("at least X"). Combines
with rate mode for free by construction — `P(hourly precip ≥ 1 mm/h)` — which is the payoff
of the §0.3 ordering rule.

* **G18 — a 20-member probability is quantized to 5 % and is not calibrated.** `P` can only
  take values `k/20`; printing "47.3 %" is false precision — show `45 % (9/20 members)`. At
  `p = 0.5` the binomial standard error on 20 members is ≈ 11 %, so small map-to-map
  differences are noise. Colorbar hard-fixed to 0–1, ignoring the scale combo.
* Draw a horizontal threshold line on `PlotView` so the map's percentage is visibly the
  count of member curves above the line — one line of code, and it turns a number into an
  explanation.

### 5.2 Wind speed and direction

Needs `U_10M` + `V_10M`, so it is the first thing that breaks "one file = one dataset".
`WSPD_10M = hypot(u, v)`; `WDIR_10M = (270 − degrees(atan2(v, u))) mod 360`, meteorological
convention (**direction the wind comes FROM**). Verified test vectors:

| wind | u | v | direction |
|---|---|---|---|
| from N | 0 | −1 | 0° |
| from E | −1 | 0 | 90° |
| from S | 0 | +1 | 180° |
| from W | +1 | 0 | 270° |
| from NE | −1 | −1 | 45° |

* **G16 — direction is circular data; linear statistics on it are wrong.** Measured: the
  linear mean of 350° and 10° is **180.0°**; the correct vector mean is **360.0°**. Ensemble
  mean direction must come from the mean *vector*; **min / max / P10 / P90 of direction are
  not meaningful** and must be shown as `n/a (circular)` rather than as a wrong number.
* **G17 — member correspondence across two files must be verified, not assumed.** Per
  **G1**, member identity is positional and survives only in `history`. If U and V were
  merged in different orders, `hypot(u[i], v[i])` combines two *different* members and looks
  entirely plausible. Compare `member_labels` element-for-element; refuse to pair on
  mismatch.
* Label which quantity is on screen: mean of member speeds `mean(|Vᵢ|)` ≥ speed of the mean
  vector `|mean(Vᵢ)|` by Jensen. The forecaster wants the former.

## 6. v3 — plan

### 6.1 Side-by-side fields *(≈ 8 h)*

All 15 fields of one run share the grid and time axis (`CLAUDE.md` §0.3), so **one shared
cursor `(t, iy, ix)` applies to all of them**. That is the whole design.

1. **`Workspace`** replaces `MainWindow.ds`: an ordered list of `FieldView`s plus one shared
   cursor. `MainWindow` becomes a view onto it, and the single-field case is a workspace of
   length 1 — the R1/v2 path is preserved, not forked.
2. **Layout**: left panel becomes a 1×N / 2×2 grid of `MapView`s with ViewBoxes linked via
   `setXLink`/`setYLink` — pan one, pan all. Right panel becomes stacked `PlotView`s on a
   shared x axis, each with its own y axis and units (a shared y across fields would be
   meaningless).
3. **Loading**: "Add field…" scans the open file's directory for the same
   `ICON_ENS_<run>_*` prefix and offers the fields present. Each add is another decompress
   + memmap, so surface the cache budget here.
4. **The reason to build it — joint probability.** `P(CAPE ≥ 1000 AND precip ≥ 1 mm/h)` must
   be evaluated **per member** and then counted:
   ```python
   joint = ((cape.ens_frame_raw(t) >= c_thr) & (prec.ens_frame_raw(t) >= p_thr)).mean(axis=0)
   ```
   Computing it from the aggregated fields is the classic error: it destroys member
   correspondence, and `P(A∧B) ≠ P(A)·P(B)` because CAPE and precip covary strongly. This
   depends on **G17**-style member-label agreement across every field in the workspace —
   verify once at add time.
5. **Cross-run consistency** (`CLAUDE.md` Phase 7's other half): same field, same point, N
   consecutive runs overlaid with the x axis on *valid* time rather than forecast hour.
   Run-to-run agreement is how a forecaster builds confidence in a signal, and it is the
   same `Workspace` with a different pairing rule.

**Done when:** CAPE and TOT_PREC open side by side, one click drives both graphs, panning
either map pans the other, and the joint-probability map is verifiably the per-member
intersection (assert against a hand-computed count on a synthetic 3-member fixture).

### 6.2 Built-in downloader *(≈ 6 h)*

Turns "there's a new run" → "I'm looking at it" into one click. `CLAUDE.md` Phase 8, with
security made explicit. **Promotes the V2.1 sniffer's auth and listing code into the app.**

1. `imsicon/download.py` — `requests` + `requests-ntlm` (**G7**).
2. **Credentials.** `keyring` (Windows Credential Manager / macOS Keychain) first, env vars
   `IMS_USER`/`IMS_PASS` second, prompt last. **Never `QSettings`** — plaintext on disk.
   Never logged, never in a URL or query string, never committed. On failure say
   "authentication failed" without echoing what was tried.
3. **Listing.** Scrape the IIS HTML index of `/ims/IMS_ICON_ENSEMBLE/` as *untrusted input*:
   match `ICON_ENS_<10 digits>_<FIELD>.nc.bz2` with a strict regex, ignore everything else,
   and never build a local path from a server string without `Path(name).name` sanitisation.
4. **UI.** "Download from IMS…": run date (~1 month rolling, 00 UTC only) × field, showing
   size and whether it is already cached. Resumable `Range` downloads into `<name>.part`,
   size-checked against the listing, atomically renamed — the pattern `ingest.decompress`
   already uses. One transfer at a time.
5. **Free win from §1.2:** the dialog can show each field's units and t=0 range *before*
   committing to a 262 MB download, using the same 4 MiB prefix sniff.
6. Chain straight into the existing decompress → open path, so a download lands the user in
   the viewer with no second file dialog.

**Done when:** a field can be picked, downloaded, decompressed and rendered without leaving
the app; an interrupted download resumes rather than restarting; and no credential appears
in a log, URL, settings file or traceback.

### 6.3 Parked ideas

Recorded so they are not re-invented: wind-sector probability `P(dir ∈ [a, b])` on a proper
arc; hodographs from the derived wind; percentile-of-climatology once more than one month of
runs is retained; a "member N vs ensemble" difference map.

### 7.2 Gotchas found while building v2

* **G25 — QSettings in tests writes the developer's real preferences.** v2 persists a units
  choice per field, so the first test run silently set `units/T_2M` in the real macOS plist
  and later tests read it back, making them order-dependent and green-or-red by accident.
  `tests/conftest.py` now redirects `QSettings` to a temp dir and clears it per test.
* **A truncated prefix still declares 121 records.** `nc3.view` builds an `as_strided` view
  from the header, and `as_strided` does not bounds-check — an unclamped `numrecs` over a
  4 MiB prefix is a segfault, not an exception. `sniff_headers.clamp_to_available` shrinks
  `numrecs` to what the buffer actually holds before any view is created.
* **G26 — a truncated `.nc` segfaults rather than raising.** The header carries `numrecs`,
  so a partially-downloaded file parses as 121 steps while holding 9, and `as_strided` does
  not bounds-check. Found while opening real prefixes as datasets. `nc3.parse` clamps,
  `nc3.view` drops a partial trailing element, and the status bar says *incomplete file*.
  This also means a prefix is a perfectly good test dataset — which is how the real-data
  checks above were run without downloading 262 MB per field.
* **The `mean` branch needed the G24 clamp too, with an amplified floor.** Its noise is
  `ulp(A)·h`, not `ulp(A)`: by +22 h that is ~1e-3 W m⁻², two orders above the raw ulp.
  Without it the night-time rate showed `-0.001` instead of `0`.
* **`spread` is a difference too.** `max − min` must not take an affine offset (**G15**).
  `FieldView.agg_frame` converts the member stack *before* aggregating, which makes spread —
  and a hypothetical negative scale, which would swap max and min — correct by construction
  rather than by a special case.
